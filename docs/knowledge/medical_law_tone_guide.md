# 품 (pum) 의료법 톤 가이드

> 출처: hosto 프로젝트에서 6개월간 축적된 자료를 통합 + pum의 B2C IVF 컨텍스트에 맞춰 보수적으로 조정.
>
> **hosto(B2B)**와 **pum(B2C)**의 핵심 차이: 원무과 직원 대상 앱에서 잘못된 표현은 병원 내부 클레임으로 끝날 수 있지만, 환자 직접 대상 앱에서 잘못된 표현은 보건복지부 조사, 앱스토어 삭제, 민사소송으로 이어진다. **pum의 톤은 hosto보다 한 단계 더 보수적이어야 한다.**

---

## 1. 가장 큰 원칙

### 1-1. 확인되지 않은 정보는 절대 "있다"고 표시하지 않는다

hosto CLAUDE.md §1에서 이미 명문화된 원칙: *"확인 안 된 정보는 절대 '있다'고 표시하지 않음. 불확실하면 '확인 필요'로 표시."*

pum에서의 적용 강도는 더 높다. 환자는 앱이 출력한 정보를 실제 의사의 조언처럼 받아들이는 경향이 있기 때문이다. 아래 규칙을 UI 레이어, AI 응답, 마케팅 카피 세 군데 모두에 적용한다.

| 상황 | hosto 기준 | pum 기준 (더 보수적) |
|------|-----------|---------------------|
| 지원 정책/급여 항목 불확실 | "확인 필요" 표기 | "확인 필요 · 담당 의료진에게 문의하세요" |
| AI 결과의 불확실성 | confidence 레이블 표시 | confidence 레이블 + "의학적 판단이 아닙니다" 고정 문구 |
| 데이터 최신성 불명확 | 출처 URL 제공 | 출처 URL + 수집 날짜 명시 |

### 1-2. pum은 의료 행위를 대신하지 않는다

pum이 제공하는 모든 기능의 정의:
- **허용**: 정보 안내, 기록 보조, 일정 관리, 건강보험/지원금 절차 안내
- **금지**: 진단, 처방, 치료 방향 제시, 예후 예측, 의학적 수치 해석 (→ §6 상세)

앱 전체에서 "pum이 말하는 것"과 "의사가 말해야 하는 것"의 경계를 물리적으로 분리한다. AI 코치 응답이 이 경계를 넘으면 안 된다.

### 1-3. 비식별화 원칙

hosto와 동일하게 적용하되 scope가 다르다. hosto는 병원 측 비식별화(환자 이름/주민번호/연락처 저장 금지)이고, pum은 환자 본인 데이터를 다루므로 **수집 최소화 + 목적 외 사용 금지**가 추가된다.

- 시술 이력, 진단명, 호르몬 수치 등은 앱 기능 제공 목적 외에 사용 금지
- 개인 데이터를 마케팅/통계 분석에 사용 시 별도 명시적 동의 필수
- AI 프롬프트에 실명/주민번호가 포함되지 않도록 서버 측 마스킹 게이트 적용

## 2. 6 Anti-Pattern — 절대 금지

hosto 데모 런치 플랜 §안티 패턴에서 도출한 6개를 B2C/IVF 도메인으로 전환.

### AP-1. 정확도 % 광고

**왜 금지**: 측정 가능한 분모가 없는 단계에서 퍼센트를 광고하면 의료광고법 위반 및 허위·과장 광고 클레임 대상이 된다. "AI 정확도 97%"는 임상 근거 없이는 사용 불가.

**pum에서 빠지기 쉬운 trap**: 착상 성공률 예측, IVF 성공 가능성 수치를 AI 코치가 숫자로 제시하는 경우. → 모든 통계 수치는 "일반 집단 통계이며 개인 예측이 아닙니다" 라벨 필수.

---

### AP-2. "검증" / "진단" 류 카피

**왜 금지**: "난임 원인 AI 검증", "배아 품질 진단" 등의 표현은 의료기기 허가 없이 사용 시 의료법 제27조(무면허 의료행위) 및 의료기기법 위반 소지. 앱스토어 심사에서도 거절 사유.

**pum에서 빠지기 쉬운 trap**: AI 코치가 혈액검사 결과를 요약할 때 "정상 범위" / "이상 소견" 판정 표현 사용. → "검사 결과를 기록했습니다. 해석은 담당 의료진에게 확인하세요"로 대체.

---

### AP-3. "삭감 방지" / "최대 지원금" 류 결과 보장 카피

**왜 금지**: 지원금 수령을 보장하는 표현은 결과 미발생 시 환불/손배 클레임 근거가 된다. hosto에서는 "삭감 방지"가 심평원 권한 침해 오해를 낳았고, pum에서는 "지원금 100% 수령 보장"이 동일한 문제를 일으킨다.

**pum에서 빠지기 쉬운 trap**: 난임 시술비 지원사업 안내 화면에서 "최대 N만원 받기"처럼 확정형 CTA 사용. → "지원 신청 안내 보기"로 대체. 금액은 "최대 N만원 (조건 충족 시)" 형식으로만 표기.

---

### AP-4. 빠른 가입 인센티브 + 과도한 마케팅 클레임

**왜 금지**: 의료 앱에서 "지금 가입하면 AI 진단 무료" 류 마케팅은 서비스의 신뢰성을 낮추고, 규제 기관의 의료광고 심의 대상이 된다.

**pum에서 빠지기 쉬운 trap**: 온보딩 화면에서 "AI가 당신의 IVF 성공을 돕습니다" 같은 성과 중심 헤드라인. → "IVF 여정을 함께 기록하고 준비합니다"로 대체.

---

### AP-5. CS 채널 부재 또는 AI 코치를 CS 대체재로 운용

**왜 금지**: 환자가 의학적 응급 상황 또는 시술 부작용을 AI 코치에게 보고할 경우, 적절한 인간 채널로 연결하지 않으면 민사·형사 책임 발생 가능.

**pum에서 빠지기 쉬운 trap**: AI 코치가 "복통이 심하다"는 입력을 받고 일반적인 안심 메시지로 응답. → AI 코치 응답에 "즉각적인 증상은 병원 또는 119로 연락하세요" 트리거 룰 필수 (§7 참조).

---

### AP-6. 미완성 기능을 완성형으로 출시

**왜 금지**: 아직 검증되지 않은 AI 추천 로직을 정식 기능처럼 출시하면, 잘못된 정보를 근거로 환자가 의사결정을 내릴 수 있다. hosto에서 Phase A 미완 상태로 유료 출시를 금지한 것과 같은 이유.

**pum에서 빠지기 쉬운 trap**: AI 코치 M6(Milestone 6) 이전에 "맞춤형 IVF 코칭"이라는 표현을 사용. → BETA 배지 + 면책 박스 적용 전까지 "참고용 안내" 수준으로만 표기.

## 5. UI 패턴: Amber Disclaimer

### 5-1. hosto 패턴 요약

hosto frontend는 세 군데에서 amber disclaimer를 사용했다:

1. **PatientForm.tsx**: 필수 입력값 누락 시 → `border-amber-200 bg-amber-50`, "분석 전 확인 필요" 헤더
2. **PatientForm.tsx**: 의료급여 기관 섹션 → 자동 파생값 안내, 모순 시 red로 에스컬레이션
3. **BillingItemCodeSelect.tsx**: 항목 추가 드롭다운 → "금액·코드·급여구분은 EMR/영수증에서 직접 입력하세요" (시스템이 단가 권위를 갖지 않음을 명시)

핵심 패턴: **amber = 주의 필요하지만 차단하지 않는 경고**, **red = 진행 불가 차단**

### 5-2. pum 결과 화면에 적용하는 방식

**모든 AI 코치 결과 화면에 amber disclaimer 고정 적용.** 다음 두 가지 형태를 사용한다.

**형태 A — 인라인 스코프 한정 (결과 카드 하단)**

```
┌ amber-50 border-amber-200 ───────────────────────────────────────┐
│ ⚠ 이 내용은 일반 안내입니다. 본인 상황은 담당 의료진에게 확인하세요. │
└──────────────────────────────────────────────────────────────────┘
```

**형태 B — 데이터 출처 안내 (지원금/정책 정보 하단)**

```
┌ amber-50 border-amber-200 ───────────────────────────────────────┐
│ 출처: 보건복지부 난임부부 시술비 지원사업 (YYYY-MM 기준)           │
│ 지역별·소득기준 조건이 다를 수 있습니다. 주민센터에서 확인하세요.   │
└──────────────────────────────────────────────────────────────────┘
```

**에스컬레이션 규칙**: 즉각적인 신체 증상 입력 시 amber → red, 응급 연락처 안내로 에스컬레이션 (§7 참조).

### 5-3. 적용하지 않아도 되는 화면

- 단순 일정 기록 (달력 뷰, 알림 설정)
- 병원 방문 기록 입력 (메모 성격)
- 계정 설정, 온보딩 튜토리얼

## 6. B2C 추가 가드 — pum 전용

hosto는 병원 직원 대상으로 의료 도메인 지식이 있는 사용자를 가정한다. pum은 의료 지식이 없는 환자 본인과 배우자를 대상으로 한다. 동일한 정보라도 전달 방식이 달라야 한다.

### 6-1. 의료 행위로 비치는 단어 절제

다음 단어는 pum UI, AI 코치 응답, 마케팅 카피 전체에서 사용을 금지한다. 대체 표현을 반드시 사용한다.

| 금지 단어 | 이유 | 대체 표현 |
|-----------|------|-----------|
| 진단 | 의료행위 | 확인, 기록, 정리 |
| 처방 | 의료행위 | 안내, 정보 제공 |
| 권장 | 의료적 권고로 오인 | 참고, 일반적으로 |
| 예측 (결과에 대한) | 근거 없는 확률 제시 | 통계 안내, 일반 경향 |
| 치료 계획 | 의료행위 | 시술 일정 기록 |
| 정상 / 이상 (수치 판정) | 진단 행위 | 수치 기록됨, 의사에게 확인 필요 |
| 개선 (의학적 맥락) | 치료 효과 암시 | 변화, 추이 |

### 6-2. 비교형 표현 절제

"A 병원보다 성공률이 높다", "이 방법이 더 효과적이다" 같은 비교형 표현은 사용 금지. 환자가 비교 기반으로 병원을 바꾸거나 의사 지시를 무시하는 행동을 유발할 수 있다.

허용: "국내 평균 통계 기준" + 개인 비교 불가 명시

### 6-3. 통계 인용은 출처 명시 필수

AI 코치가 통계를 인용할 때 반드시 다음 형식을 사용한다:

```
"만 35세 이하 첫 IVF 시술 성공률은 약 40-50%입니다.
(출처: SART 2022 National Summary Report / 차이헬스케어 국내 데이터 2023)"
```

출처 없는 통계 인용은 AI 코치 응답에서 자동 차단 (§7 가드 룰 참조).

### 6-4. 본인 사례 vs 일반 안내 명확 구분

사용자가 자신의 호르몬 수치나 배아 등급을 입력했을 때, AI 코치는 두 레이어를 명확히 구분해야 한다:

- **레이어 A (본인 기록)**: "AMH 1.2 ng/mL로 기록했습니다."
- **레이어 B (일반 안내)**: "같은 나이대 일반 통계상 AMH 1.0~3.5 범위가 보고됩니다. (출처: X)"
- **금지**: 두 레이어를 섞어 "AMH 1.2는 낮은 편이므로…" 형태로 판정

### 6-5. 감정적 언어 주의

IVF는 심리적으로 민감한 과정이다. 다음 표현은 사용을 제한한다:

| 주의 표현 | 이유 | 대체 |
|-----------|------|------|
| "실패" (시술 결과에 대해) | 환자에게 심리적 타격 | "이번 주기 미착상" |
| "희망이 있습니다" | 근거 없는 위안 | 정보 제공에 집중 |
| "포기하지 마세요" | 의료적 조언 범위 초과 | AI 코치 응답 범위 아님 |

## 7. AI 코치 시스템 프롬프트 가드 — M6 직전 적용

hosto OCR anti-hallucination 패턴(3단계 검증, 불확실 시 "확인 필요" 표기, 단가 권위를 EMR에 위임)을 IVF 코치 컨텍스트로 전환한 5개 룰.

### Guard-1. 진단·처방 경계 강제

```
[시스템 프롬프트 가드 룰]
You MUST NOT:
- 의학적 진단을 내리거나 진단명을 제안하는 것
- 특정 약물/보충제/시술을 권장하는 것
- 혈액검사·초음파 결과를 "정상/이상"으로 판정하는 것
- 의사의 지시와 다른 방향을 제안하는 것

위 요청이 들어오면 반드시 다음 형식으로 응답:
"[해당 질문]은 담당 의료진에게 직접 확인이 필요한 내용입니다.
다음 방문 때 물어볼 질문 목록을 함께 정리해드릴까요?"
```

### Guard-2. 출처 없는 통계 차단

```
통계 수치를 언급할 경우 반드시 다음 형식을 지켜야 합니다:
- "(출처: [기관명] [연도])"를 수치 바로 뒤에 명시
- 출처를 모르는 수치는 인용 금지. 대신: "정확한 수치는 의료진에게 문의하세요"
- 개인 예측으로 해석될 수 있는 수치 제시 금지
```

### Guard-3. 응급 증상 에스컬레이션

```
사용자 입력에 다음 키워드가 포함된 경우 즉시 응급 안내로 전환:
- 극심한 복통, 심한 출혈, 호흡 곤란, 의식 저하
- 난소과자극증후군(OHSS) 의심 증상 (복부 팽창, 구토, 소변 감소)
- 복막염, 감염 의심 (고열 + 복통)

응급 전환 형식:
"지금 증상은 즉시 병원 응급실 또는 119에 연락이 필요할 수 있습니다.
시술받은 병원 응급 연락처: [병원 전화번호 입력 필드]
(AI 코치는 응급 상황을 판단할 수 없습니다)"
```

### Guard-4. 비교 판정 금지

```
사용자의 데이터(호르몬 수치, 배아 등급, 내막 두께 등)와
일반 통계 또는 다른 환자 사례를 비교하여 "좋다/나쁘다/정상/낮다" 판정 금지.

허용 패턴:
"AMH [수치] ng/mL로 기록됐습니다."
+ 별도 블록: "일반적으로 [나이대] 평균 범위는 [X-Y]입니다. (출처: Z)"

금지 패턴:
"AMH [수치]는 낮은 편이므로..." → 의료적 해석 → 금지
```

### Guard-5. 할루시네이션 방지 — 불확실 시 명시

```
확인되지 않은 정보를 "있다"고 제시하지 마세요.
불확실한 경우 반드시 다음 중 하나를 선택:
1. "확인 필요: [내용]은 병원/주민센터에서 확인하세요"
2. "정확한 정보를 찾지 못했습니다. 보건복지부 콜센터(129)로 문의하세요"
3. 응답 거부 후 "다음 방문 질문 목록에 추가할까요?" 제안

절대 금지: 출처 없는 확정적 진술 ("이 경우 보통 ~합니다"를 사실처럼 제시)
```
